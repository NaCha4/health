# 신체정보와 음식 및 소비열량 계산 설계

체중 관리의 원본은 신체정보, 먹은 음식과 분량, 실제 활동 기록이다. dot는 음식과 활동을 해석하고 근거를 찾아 기록한다. 수치 계산은 Firebase 서버가 담당하며, 화면이나 dot에서 조회할 때 최신 입력으로 다시 계산한다. 이 문서는 구현할 동작을 정의하며 현재 계산 기능이 구현된 상태는 아니다.

## 저장할 정보와 다시 계산할 정보

| 저장할 원본과 판단 근거 | 조회하거나 입력을 바꿀 때 계산할 값 |
| --- | --- |
| 키, 체중, 나이 기준일 또는 생년월일, 대사식 계수 선택, 적용 날짜 | 해당 날짜의 안정 시 대사량 추정 |
| 체지방률, 허리둘레, 측정 장비와 시각 등 선택 신체정보 | 신체 변화 추이와 기간 평균 |
| 음식명, 제품·브랜드, 섭취량, 조리 상태, 영양정보 출처와 버전 | 음식·끼니·하루별 섭취 열량과 영양소 합계 |
| 사진 해석, 추정 분량의 하한·대표값·상한, 가정과 근거 | 섭취량의 추정 범위 |
| 운동 종목, 실제 수행 시간, 속도·강도, MET 항목과 출처 | 운동 소비열량과 기준 활동 대비 추가 소비량 |
| 평소 생활 활동, 기준선에 포함된 활동, 적용 기간 | 하루 총소비열량과 섭취·소비 차이 |

dot의 대화 메모에 매번 하루 합계를 저장하지 않는다. 근거가 있는 음식 기준값과 추정 전제는 다시 찾을 수 있도록 보관한다. 재사용하는 것은 출처가 있는 기준값이며, 과거에 생성한 합계를 현재 값으로 간주하지 않는다.

## 신체정보 기록

dot가 사용자의 발언에서 신체정보를 추출해 기록할 수 있게 한다. 키는 cm, 체중은 kg로 정규화하고 사용자가 말한 원래 값과 단위도 보존한다. 체중 외에 체지방률, 근육량, 허리둘레, 검사·측정기관의 대사량을 선택 기록으로 지원한다.

계산에 필요한 키·나이·체중·계수 선택이 부족하면 필요한 항목만 묻는다. 이름이나 사진으로 나이 또는 대사식의 성별 계수를 추측하지 않는다. 생년월일 대신 기준일이 있는 만 나이를 입력할 수 있게 하고, 이 경우 정확한 생일을 아는 것처럼 자동 갱신하지 않는다.

신체정보마다 측정일과 적용일을 둔다. 과거 하루를 계산할 때는 그날 유효한 신체정보와 그날 또는 이전의 가장 가까운 유효 체중을 사용하고, 체중 측정일을 표시한다. 과거 기록이 전혀 없으면 이후 측정값을 몰래 대입하지 않는다. 오래된 체중을 사용하는 경우 그 날짜를 표시하고 갱신을 제안한다.

체성분 장비가 제공한 기초대사량도 장비의 산출값인지 직접 측정한 값인지 구분한다. 장비 숫자를 무조건 실측 대사량으로 취급하지 않는다.

## 음식의 영양정보 검색과 추정

dot에게 음식 사진, 영양성분표, 제품명 또는 식사 설명을 전달하면 다음 순서로 처리한다.

1. 실제로 먹은 기록인지, 먹기 전 비교·질문인지 구분한다. 사진을 보여주었다는 이유만으로 섭취 기록을 만들지 않는다.
2. 제품명·브랜드·조리 상태와 먹은 분량을 파악한다. 음식 사진만 있으면 보이는 음식과 확인이 필요한 부분을 나눈다.
3. 사용자가 제시한 해당 제품의 영양성분표, 제조사·식당 공식 정보, 공공 영양 DB 순으로 적합한 자료를 찾는다.
4. 정확히 맞는 자료가 없으면 유사 음식 또는 재료별 자료로 추정한다. 확인되지 않은 재료·양·기름·소스는 추정 전제로 기록한다.
5. 서버가 단위와 분량을 환산해 대표값 및 가능한 범위를 계산한다. dot는 근거와 가정을 짧게 설명한다.
6. 섭취가 확인된 기록은 추정 상태로 저장할 수 있다. 음식 종류나 분량에 따라 결과가 크게 달라지는데 근거가 부족하면 핵심 사항만 확인한다.

국내 음식 검색은 식약처 K-FIND를 우선 후보로 사용한다. 보완 자료로 USDA FoodData Central의 음식 검색·상세 조회를 활용할 수 있다. 연동은 API 또는 허용된 데이터셋을 검토하며, 정확한 제품·기준 분량을 맞추는 것을 우선한다. [K-FIND 식품영양성분 DB](https://various.foodsafetykorea.go.kr/nutrient/), [USDA API 안내](https://fdc.nal.usda.gov/api-guide/)

한 번 조회한 식품은 출처 ID, 자료명·URL, 조회일, 자료 버전, 100g 또는 1회분 기준량, 열량과 영양소, 조리 상태를 보관한다. 포장 전체와 1회분, 조리 전과 조리 후, 제공량과 실제 섭취량을 구분한다. 물·기름·소스를 포함하는지 확인하고 g와 ml를 밀도 근거 없이 같은 값으로 바꾸지 않는다.

기본 환산은 `섭취 열량 = 기준 열량 × 섭취량 ÷ 기준량`이다. 한 끼 전체 추정값을 저장한 경우 재료별 추정치를 또 더하지 않는다. 사용자가 식사 전체 kcal만 알려주면 그 값을 사용할 수 있지만, 영양소까지 임의로 역산하지 않는다.

자료의 열량이 이미 있으면 그 값을 우선하고, 영양소 환산은 보조 추정으로 구분한다. 영양표의 반올림이나 식이섬유·알코올 등 때문에 서로 다른 계산 결과가 나올 수 있으므로 출처 숫자를 조용히 덮어쓰지 않는다.

### 추정치의 표시와 수정

음식 식별, 분량, 영양 기준값의 근거 수준을 각각 표시한다. 영양표를 정확히 읽었어도 섭취량을 사진으로 추정했다면 전체 섭취 열량은 추정이다. 하한·상한을 정할 근거가 없다면 임의의 오차율을 붙이지 않고 대표 추정 또는 미상으로 표시한다. 범위를 제시할 때는 통계적 신뢰구간이 아닌 가정별 시나리오 범위임을 명시한다.

사용자가 “반만 먹었어”, “소스는 안 먹었어”라고 정정하면 해당 음식의 분량·재료만 수정하고 끼니와 하루 합계를 다시 계산한다. 새 영양 DB 버전이 나와도 과거 식사의 기준값을 자동 교체하지 않는다. 자료 교정이 필요할 때 별도 수정 이력으로 반영한다.

첫 버전은 dot 대화에서 제공받은 사진·설명을 해석하고 구조화된 결과를 홈페이지에 저장한다. dot가 사진을 읽을 수 있는 실제 경로를 연동 시험에 포함한다. 사진 파일의 홈페이지 보관·앨범과 홈페이지에서 직접 AI 분석을 시작하는 기능은 별도 기능으로 구분한다.

## 안정 시 대사량과 하루 소비열량

### 대사량 계산식

성인용 기본 후보는 Mifflin–St Jeor 식이다. 이 식의 대상은 안정 시 에너지 소비량 REE이며, 측정된 기초대사량 BMR과 같다고 표시하지 않는다. 화면에는 “안정 시 대사량 추정 · 기초대사 참고”로 표시한다.

`REE kcal/일 = 10 × 체중 kg + 6.25 × 키 cm − 5 × 만 나이 + 계수`

원 논문의 남성 계수는 +5, 여성 계수는 −161이다. 계수 선택은 사용자 입력을 기준으로 하며 미선택 시 임의로 결정하지 않는다. 공식 식별자·버전과 사용한 입력값을 결과에 연결한다. [원 논문](https://pubmed.ncbi.nlm.nih.gov/2305711/)

개인의 실제 소비량은 식만으로 확정할 수 없다. 기본 자동 계산은 일반 성인용 추정으로 범위를 정하고, 미성년자·임신·수유 등 별도 산정이 필요한 조건에는 이 기본 모델을 자동 적용하지 않는다. 기록 기능은 사용할 수 있다. [NIDDK의 성인용 계산 도구 적용 범위](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)

### 운동 소비량

종목과 속도·강도에 맞는 Compendium의 MET 항목을 선택하고 출처 항목과 버전을 저장한다. 표준 MET는 `1 MET ≈ 1 kcal/kg/시간`을 사용하는 근사치이므로 다음과 같이 계산한다. 사용자의 신체조건에 따른 오차가 있으며 결과는 추정값으로 표시한다. [MET 정의와 활동 자료](https://pacompendium.com/), [개인차에 관한 안내](https://pacompendium.com/corrected-mets/)

- 운동 중 총소비 추정: `MET × 체중 kg × 수행 시간 h`
- 안정 상태 대비 순증가: `(MET − 1) × 체중 kg × 수행 시간 h`
- 하루 기준선 대비 추가 소비: `(운동 MET − 대체된 기준 활동 MET) × 체중 kg × 수행 시간 h`

셋은 의미가 다르므로 필드와 화면 이름을 구분한다. 시간 분은 시간 h로 환산하고, 근력운동의 휴식 시간을 고강도 수행 시간으로 계산하지 않는다. 운동 강도를 특정할 수 없으면 여러 적합한 활동 후보에 따른 범위 또는 계산 보류 상태를 반환한다.

### 하루 총소비 추정 방식

첫 버전은 **운동을 제외한 하루 기준선에 해당 운동이 추가한 소비량을 반영하는 방식**을 제안한다. 아래 조합은 서비스의 근사 모델이며 개인에게 검증된 직접 측정값으로 표현하지 않는다.

`하루 예상 총소비 = REE × 비운동 생활활동계수 + 각 운동의 기준선 대비 추가 소비 합계`

생활활동계수는 수면, 앉아서 일하는 시간, 서거나 걷는 일상, 식이성 발열의 평균적 영향을 포함한 비운동 하루 기준선을 나타낸다. dot가 사용자의 생활 설명을 바탕으로 출처와 가정을 제시해 설정하고, 자동으로 추정한 계수는 추정 상태로 저장한다. 검증되지 않은 고정 계수를 모든 사람에게 적용하지 않는다. 기반 자료와 계수 설정 규칙을 구현 시 확정하고, 설정이 없으면 REE와 운동 추정만 보여주며 총소비는 미산정으로 둔다.

운동을 포함한 일반적인 활동계수로 총소비를 구하는 방식을 선택했다면 그 운동을 다시 더하지 않는다. 이 경우 식은 `REE × 전체 활동계수`이며 위 방식과 섞지 않는다. 기준선에 식이성 발열이 포함되면 섭취 열량의 일정 비율을 또 추가하지 않는다.

운동을 하는 동안 원래 무엇을 했을지에 따라 대체 기준 활동을 정한다. 알 수 없으면 가정을 명시한 추정 또는 범위를 사용한다. 그 운동이 기준선에 이미 포함되어 있는지 확인되지 않으면 합산에서 보류하고 이유를 표시한다. 근사 모델의 편의를 위해 계산에 들어간 전제를 숨기지 않는다.

걷기 운동과 걸음 수, 운동기기와 수동 기록이 같은 활동을 가리키면 하나만 반영한다. 기기가 제시한 하루 총소비를 사용할 때는 REE와 운동을 다시 더하지 않는다. 기기의 활동 칼로리·전체 칼로리도 구분하며 첫 버전에서는 별도의 비교값으로 둘 수 있다.

### 하루 중 표시 방식

오늘의 식사는 “현재까지 기록된 섭취량”, 전체 소비 모델의 결과는 “하루 예상 소비량”으로 표시한다. 하루 예상 소비량을 지금까지 이미 소비한 열량처럼 보여주지 않는다. 완료 운동과 계획 운동을 구분하고, 계획 운동은 별도의 시나리오에만 넣는다.

하루가 끝난 뒤에도 소비량은 추정값이다. 식사 기록이 미완료이거나 열량 미상인 식사가 있으면 확정적인 적자·흑자 판정을 하지 않는다. 추정값이 포함된 경우 출처와 범위를 함께 보여준다.

완료된 기록의 추정 적자는 `소비 − 섭취`로 정의한다. 양수는 적자, 음수는 흑자다. 섭취 범위가 I_low~I_high, 소비 범위가 E_low~E_high이면 적자 범위는 `E_low − I_high`부터 `E_high − I_low`다. 이 범위가 0을 포함하면 방향을 단정하지 않는다. 계산된 차이를 자동으로 추가 섭취 권장량이나 확정 감량량으로 바꾸지 않는다.

## 실시간 재계산과 이력

실시간은 **원본을 수정하거나 화면·도구가 조회할 때 최신 상태로 계산한다**는 의미다. 계속 모델을 호출하거나 모든 기록을 매초 다시 읽지 않는다.

1. 식사·운동·신체정보와 계산 전제가 바뀌면 데이터 버전을 갱신한다.
2. 화면과 dot가 같은 서버 계산 함수를 호출한다.
3. 날짜, 기준 시각, 유효한 신체정보, 영양 기준값 버전, 활동 기준선, 계산식 버전으로 결과를 만든다.
4. 같은 입력의 캐시는 재사용하고 입력 또는 날짜 경계가 달라지면 무효화한다.
5. 한 요청은 일관된 데이터 버전을 사용한다. 계산 중 버전이 바뀌면 다시 계산하거나 변경 전 기준임을 표시한다.

반환값에는 대표값, 근거 있는 범위, 단위, 입력 기록 ID, 적용 공식, 계산 시각, 누락 입력, 추정 전제와 데이터 버전을 포함한다. dot는 이 결과를 설명하며 자체 계산으로 다른 합계를 만들지 않는다.

새 체중 입력은 해당 날짜 이후의 계산에 적용한다. 과거 날짜로 정정한 입력은 영향을 받는 과거 기간도 다시 계산한다. 보고서는 당시 결과를 스냅샷으로 보관하되 현재 계산과 구분하고, 관련 원본이 바뀌면 재검토 표시를 붙인다.

## 데이터와 MCP 확장

기존 `weight_entries`, `meal_entries`, `workout_entries`에 더해 다음 저장 단위를 둔다.

| 저장 단위 | 역할 |
| --- | --- |
| body_profiles | 시점별 키·나이 정보·대사식 계수 선택과 선택 신체 지표 |
| activity_baselines | 일상 활동 설명, 계수·대체 활동, 포함된 운동, 적용 기간과 근거 |
| food_references | 식품별 기준 영양정보와 출처 스냅샷, 기준 단위와 조리 상태 |
| meal_items | 끼니별 음식, 섭취 분량·추정 범위, 참조 영양정보와 수정 이력 |

계산 결과는 재생성 가능한 캐시로 둘 수 있지만 원본 테이블처럼 직접 수정하지 않는다. 신체정보와 음식 추정 변경은 일반 기록과 동일하게 소유자·버전·수정 이력을 확인한다.

| 도구 제안 | 동작 |
| --- | --- |
| record_body_profile | 사용자가 제공한 신체정보를 적용일과 함께 기록 |
| search_food_nutrition | 조건에 맞는 음식 후보와 출처·기준 분량 조회 |
| save_meal_estimate | 음식 식별과 분량의 가정, 영양 기준값을 식사에 저장 |
| calculate_energy_balance | 날짜·기준 시각에 맞춰 REE·섭취·운동·총소비·차이를 재계산 |

검색·계산과 기록을 바꾸는 도구를 구분한다. 자유로운 웹 검색과 사진 해석은 dot가 지원하는 도구로 수행하고, Firebase는 구조화된 값의 검증과 계산을 맡는다. 영양 DB 전용 API가 필요한 경우 서버에 연결하고, 제공자 키는 브라우저용 `VITE_` 설정에 넣지 않는다. API 키 발급과 연결은 별도 준비 단계이며 현재 추가 키를 생성하지 않는다.

## 구현 검증 기준

다음 수치는 산술 검증을 위한 가상 예시이며 사용자의 건강 목표나 권장값이 아니다.

- 100g당 250kcal인 음식 180g은 450kcal다. 섭취량을 90g으로 정정하면 225kcal이며 끼니·하루 합계도 바뀐다.
- 같은 음식의 완제품 열량과 재료별 열량을 이중 합산하지 않는다.
- 체중 80kg, 키 175cm, 30세, 계수 +5의 REE는 1748.75kcal/일이다.
- 80kg, 5 MET, 30분 활동의 총소비는 200kcal, 1 MET 기준 활동 대비 추가량은 160kcal다.
- 검증용 비운동 계수 1.4와 위 추가량을 조합하면 하루 예상 총소비는 2608.25kcal다. 화면은 근사값으로 반올림하되 계산 중간에는 정밀도를 보존한다.
- 운동 포함 계수 방식에서는 운동 200kcal 또는 160kcal를 다시 더하지 않는다.
- 음식·체중·활동 기준선 수정 시 관련 계산을 갱신하고, 과거 음식 출처 버전은 임의 변경하지 않는다.
- 음식 분량·운동 시간·신체 입력이 빠지면 미산정 또는 설명된 추정 범위를 반환하고 0으로 채우지 않는다.
- 당일 미완료 식사, 미래 운동 계획, 중복 걷기 기록으로 확정 적자를 표시하지 않는다.
- 웹과 dot의 동일 날짜·동일 버전 조회 결과가 일치하고, 새 날짜·입력 버전에서는 오래된 캐시를 사용하지 않는다.
