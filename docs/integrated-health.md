# 통합 건강 기록 확장

기존 React/GitHub Pages와 Firebase Authentication·HTTP API·Firestore·OAuth MCP를 그대로 사용합니다. 약물·주사, 실제 투여, 증상, 수면을 기존 식사·체중·신체 기록과 함께 조회합니다. 사용자 약물·증상은 미리 넣지 않습니다.

## 데이터와 이력

- `medication`: 이름, 단위 포함 확인 용량(`doseConfirmed: true`), 투여 경로, 처방 일정, 적용일, 복용 중/일시 중단/중단 상태. `previousId`로 이전 처방에 연결합니다. 변경은 새 기록을 생성하며 이전 처방을 수정·삭제하지 않습니다. 같은 이전 처방에 대한 동시 변경은 하나만 저장됩니다. 미래 적용일은 그날부터 현재 일정으로 보입니다.
- `dose`: 당시 처방 ID, 한국 날짜와 실제 시각, 복용/미복용, 실제량. 실제량은 처방에서 자동 입력하지 않습니다. 미복용은 실제량이 null이며, 미기록을 미복용으로 추정하지 않습니다. 미래의 실제 투여와 계정 밖 참조를 거절합니다.
- `symptom`: 사용자가 적은 증상, 강도 0~10, 선택적 시각·지속 시간·메모. 강도 0은 증상이 없었다고 남긴 기록이며 증상 발생일/투여와의 겹침에 포함하지 않습니다.
- `sleep`: 잠에서 깬 날짜의 총수면 시간, 선택적 만족도. 날짜별 최신 수면 한 건을 사용합니다. 해당 유형이 없으면 기존 하루 점검의 수면을 사용합니다. 원본은 삭제하거나 합산하지 않습니다.

새 필드는 기존 공통 입력 스키마에 추가했습니다. 기존 종류/REST 경로/MCP 도구 이름/ID/버전/재시도 방식과 JSON 백업 형식 버전 1을 유지합니다. 새 클라이언트와 서버는 기존 백업도 읽습니다. 이전 버전의 서버는 새 기록 종류를 해석하지 못하므로 새 기록 생성 후 서버를 과거 버전으로 되돌리는 것은 피해야 합니다.

운영 데이터를 일괄 읽거나 다시 쓰는 마이그레이션은 없습니다. 등록 시 기존 트랜잭션으로 새 문서와 변경 이력만 생성합니다. JSON 복원은 기존처럼 빈 계정에만 허용하며, 쓰기 전에 처방 참조와 이력 연결도 검증합니다. 직접 Firestore 접근 거절, 소유자 allowlist, OAuth 범위와 CORS는 유지합니다.

## 요약과 분석

건강 홈의 7/30/90일 또는 직접 선택 요약은 **규칙 기반**입니다. 기록이 없는 평균은 null로 남기고 이전 같은 길이의 기간과 비교합니다. 투여 당일/다음 날의 증상 기록일이 겹치는 횟수만 관찰로 제시합니다. 증상이 먼저 발생했을 가능성, 비교 조건·기록 누락을 설명하며 인과관계를 산출하지 않습니다. 처방 일정은 자유 입력이므로 복용률·자동 예정 횟수는 계산하지 않습니다.

기존 AI 경로는 사용자가 연결된 dot에 분석을 요청하고 MCP로 노트를 저장하는 방식입니다. 관찰·가설(`hypotheses`, 기존 보고서 호환을 위해 선택 필드)·근거 ID·불확실성·제안을 나누어 표시합니다. 웹에서 새 외부 AI API를 호출하거나 자격증명을 생성하지 않습니다. 처방 생성·변경은 웹에서 사용자가 확인합니다.

`/v1/summary`와 MCP `get_health_summary`의 기존 응답에 `integrated`, `summaryMethod: rules-v1`을 추가했습니다. `get_health_context`에는 현재 일정과 통합 요약이 추가됩니다. 도구 수 11개와 기존 scope를 유지합니다.

## 내보내기와 검증

건강 홈의 기간 CSV는 실제 시각·당시 처방 ID·처방 용량/일정·실제량·수면·증상·메모와 전체 기록 JSON을 포함합니다. 설정의 종류별 CSV도 새 상세 필드를 포함합니다. JSON은 원본과 모든 변경 이력을 포함하는 기존 API를 사용합니다. CSV 수식 문자는 이스케이프합니다.

검증 명령은 기존 `npm test`, `npm run typecheck`, `npm run test:rules`, `npm run build`입니다. 모든 자동 테스트는 합성 데이터/MemoryStore 또는 명시적 loopback의 `demo-dot-health` 에뮬레이터만 사용합니다. 브라우저에서는 합성 입력·취소·반복 입력·시각/날짜 변경·재시도·저장 중 입력 잠금·인증 후 새로고침·기간 CSV와 320/390/1440px 화면을 확인합니다. 운영 기록은 조회·수정·촬영하지 않습니다.

배포는 기존 `health-6b756`의 `functions:health:api`, 이후 `main`에서 수동 Pages workflow를 사용합니다. Firestore 규칙/인덱스, 소유자, IAM, OAuth·CORS 허용 목록을 변경하지 않습니다. 기존 로컬 프로젝트에 있던 `docs/deployment.md`의 사용자 수정은 원본 폴더에 그대로 보존합니다.
